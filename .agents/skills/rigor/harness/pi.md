# pi

Verified against pi 1.5.0 and pi-subagents 0.85.0 (2026-11-07).

- **Skills.** Discovers `.agents/skills/` natively. Invoke with `/skill:<name>`. Skills with `disable-model-invocation: true` are invisible to the model, so reach pack files by path, never by name.
- **Children.** pi core has no subagent tool; the `pi-subagents` extension provides `subagent`. The bundled `worker`, `reviewer` and `scout` agents inherit the repo's instruction files (`inheritProjectContext: true`) but not the skills catalog (`inheritSkills: false`) or the global context file; a custom agent gets each only by setting it, and a `context: "fork"` child gets the parent's whole system prompt. Still deliver work as an absolute-path packet: the brief, the standing orders, and absolute paths of the files to read. The `skill:` option delivers only advertised skills: a hidden one never reaches the child prompt, even when named. Under the default `toolActivation: "auto"`, a parent on a model that can take tools mid-conversation starts with only `subagents_enable`; call `subagents_enable({})` before the first `subagent` or `bg_wait`.
- **Parallel.** One `subagent({ workflow: true })` call with `runs.all([...])` for a wave. Async is the default; `async: false` blocks.
- **Wait / loop.** When the user has a pi subagent policy skill, its async rule governs and the repo's PROJECT RULES (`docs/agents/packet-rules.md`) name its path; this note matches it. An interactive parent lets async children wake it: no `bg_wait()`, no `status` polling. A run-to-completion parent (a chain L1, any L2 that launches children, any headless pi agent or one a delegation tool drives) waits in a loop of `bg_wait({ timeoutMs: 600000 })`: 10 minutes or less, never a `bg_wait` without `timeoutMs` (its fallback window is 30 minutes). A `bg_wait` that returns early because a child needs attention is not a timeout: handle it, then wait again. On each timeout it checks each running child's progress once, nudges or interrupts a stalled one, and appends a progress-log line. Schedules are not heartbeats for children; L0's 15-minute watch runs in L0's harness.
- **Model roles.** `agentOverrides` in pi-subagents settings; read them during setup, never at runtime.
- **Child-only extensions.** In `subagentOnlyExtensions`, name a bundled pi extension as `builtin:<name>` (`builtin:codemode`, `builtin:mcp`, `builtin:tool-search`, `builtin:llama.cpp`), never by a path under `~/.pi/agent/install/releases/<version>/`: that path holds the version number and stops resolving after the next pi upgrade.
- **Transcripts.** `~/.pi/agent/sessions/--<cwd with / as ->--/*.jsonl`. `scripts/pi-delegation.mjs --for <dir>` reads the newest file there and counts one L1's `subagent` calls per child.
- **Child run budget.** A child run is cut at 30 minutes. Give a probe child (the self-review's final-loop probe) a 25-minute budget in its brief, so the cut never fires: past 20 minutes it stops and reports what ran, with the rest listed as "not run". A child that reports partial results is not resumed; the L1 counts what it proved and lists the rest as unproven in the self-review file. A child cut by the run budget anyway is not resumed either: relaunch only its unrun attacks, once, in a fresh child.
- **Child contract.** A pi child runs to the end of its own turn. A packet that gives it children must say "never end your turn while a child runs" and give the bounded wait above, or it reports before its worker or reviewer has spoken.
- **Fallbacks.** No pi-subagents: run units serially in-session and log `degraded: serial`; reviews then run as personas, labeled "single-family".
